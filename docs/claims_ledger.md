## 二、不能声称（现在写就是错的）

| 不能声称 | 为什么 | 要等到什么条件 |
|---|---|---|
| ❌「三个基线」 | 仓库里**没有 B3/LightRAG**，只有两个 | 真把 LightRAG 跑通并接入受控图（预计 3–5 天） |
| ❌ 把 FR / FFR 的具体数值直接当结论 | 全量已出（bfs2 FR=0.138、FFR=0.113），但 500 个配对里 **251 个证据没变**（翻转必然为 0），真实效应只在证据变化子集上；且 B1 的 0 是构造值 | 按证据变化分层报（0.277 vs 噪声 0.180）；并把「内容翻转」与「拒答抖动」分开 |
| ❌「翻转率显著高于噪声」 | 证据变化子集 0.277 vs 噪声 0.180，差 +0.097、近似 p=0.042；但未配对、题重叠、噪声只 100 题 → 边缘、不稳健 | 配对设计（同题同 prompt 重复 N 次）+ 更大噪声样本，或改多次采样投票 |
| ❌「FR=0.138 说明图变更让 13.8% 的答案变了」 | 0.138 是被 251 个「没换 prompt」的配对稀释后的平均值 | 见上：分层报，或只报证据变化子集 |
| ❌「漏翻转率 MFR = X」 | 全库只有 25 条「应翻」，refine 分支为 0，单格 n 为 0–12 | 扩题或改题集设计，使每格 flip ≥10 |
| ❌「数据可行性已通过」 | G0 的 verdicts 是 c=fail、b=fail、d=partial、a=unverified | 换数据源或扩种子，让三项计数 ≥400、同指对 ≥8、有干净二分 |
| ❌「四个算子都是真实语义变更」 | MERGE 输入是 12 对人工合成；RESTRICT 不是时间收窄而是属性收窄；SPLIT 负分支是补集 | 要么补真实数据（二跳 alias、P580/P582 取数），要么在论文里始终加限定词 |
| ❌「应然矩阵与先验一致」 | T1.5 只跑了 S 的草稿先验，A 的正式先验未填 | A 填 `data/prior_20grid.json` 并签名，且 commit 早于对照运行 |
| ❌「全文已就绪」 | 没有初稿，B3 缺失，题量与统计功效不足 | 见 `RESUME.md` 第 4–5 节（已知缺口与下一步） |

## 三、必须带限定词才能说的三句

1. **MERGE_ENTITY**：说「合成重复对上的合并」，不说「真实同指实体合并」。
2. **RESTRICT_REL**：说「按属性（枢纽所在国家）收窄」，不说「按时间收窄」。
3. **SPLIT_CONCEPT**：说「真实子类 + 补集类」，不说「真实二分」。补集类的名字是分析构造。
4. **FR**：说「证据变化子集上翻转 0.277，同一 prompt 重采样噪声 0.180」，不说「FR=0.138」。
   前者是效应，后者是效应与「不可能翻转的一半」的平均。

## 四、审稿人最可能问的三个问题（提前准备答案）

| 问题 | 现在的答案 |
|---|---|
| 「你的 B1 是不是空跑？它读图吗？」 | 不读图，是**负控**：v1/v2 输出应当字节相同，用来证明翻转来自图结构而非文本。必须在方法节把这句话写清，否则会被当成 bug。 |
| 「590 个实体的图，B2 两跳子图几乎一定覆盖答案，为什么还会翻？」 | 因为 B2 是**有损**的：2 跳上限、≤20 条边、禁 P279、无类型约束。这正是要测的点——信息不完整时 schema 变更才暴露。必须给出子图覆盖率统计。 |
| 「refine 分支 100 条全 stable，是不是设计有问题？」 | 是设计使然：求解器用闭包语义，而 REFINE 的形式保证闭包不变，所以该分支只能测「误翻转」、不能测「漏翻转」。**必须主动写出来**，否则 FFR/MFR 两表自相矛盾。 |

## 五、汇报时的一句话总结（当前状态）

> 数据与算子层面的形式条件已经立住（指纹可复现、闭包与互斥并集有断言），
> 基线也有了全量实测（2000 行、负控 FR=0、B2 证据变化子集 FR=0.277 vs 噪声 0.180），
> 但**数据可行性没通过**（四项里两项 fail）、**效应只比噪声高一个边缘量**、**应然矩阵没有正式先验**、**B3 缺失**，
> 所以现在能交的是"管线 + 标签 + 一张分层后的主表"，还不是"可发表的结论"。
